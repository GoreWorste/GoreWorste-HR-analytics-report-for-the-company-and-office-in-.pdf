## HR-аналитика: генерация PDF‑отчёта

Этот проект представляет собой утилиту для построения HR‑отчёта в формате PDF на основе данных из Excel‑файла.  
Скрипт анализирует данные о сотрудниках и увольнениях, рассчитывает ключевые HR‑метрики и формирует визуально оформленный двухстраничный отчёт.

## Основная логика и архитектура

- **Точка входа**: весь код расположен в `main.py`. Локальный запуск: **`.venv/bin/python main.py`** (или активируйте окружение: `source .venv/bin/activate`, затем `python main.py`). Без виртуального окружения возможна ошибка `ModuleNotFoundError: No module named 'pandas'`.
- **Источник данных**: Excel‑файл `Data.xlsx` (по умолчанию путь зашит в константу `DATA_FILE_PATH`).
- **Листы Excel**:
  - `Список сотрудников` — актуальные сотрудники (основная таблица, заголовки в строке 3 файла, `header=2`).
  - `Увольнение` — уволенные сотрудники (исторический список увольнений).
- **Основной процесс обработки**:
  1. Загрузка листов с автоматическим фоллбэком по индексу, если не найдено по имени.
  2. Нормализация и приведение данных к рабочему формату.
  3. Формирование объединённого датафрейма `df_all` для помесячного анализа.
  4. Расчёт сводных метрик и помесячных рядов.
  5. Генерация PDF‑отчёта с помощью `matplotlib` и `PdfPages`.

Все вычисления и визуализации находятся в одном файле `main.py`.

## Настройки и режимы работы

- **Источник данных**:
  - **По умолчанию данные загружаются из URL на сервере**:
    - `DATA_FILE_URL` — константа с URL файла на сервере Yandex Cloud:
      - `https://storage.yandexcloud.net/sds-hr/sds-hr/Реестр_сотрудников.xlsx`
    - Для использования другого URL установите переменную окружения `DATA_FILE_URL` или измените константу в `main.py`.
  - **Локальный файл** (опционально):
    - Если установлена переменная окружения `DATA_FILE_PATH` или передан параметр `data_file_path` в функцию `generate_report()`, будет использоваться локальный файл.
    - Приоритет источников:
      1. Параметр `data_file_path` в функции `generate_report()`
      2. Переменная окружения `DATA_FILE_PATH`
      3. URL из `DATA_FILE_URL` (по умолчанию)

- **Режим данных `DATA_MODE`**:
  - `real` — использование только фактических данных из Excel.
  - `demo` — подмена части метрик заранее заданными демонстрационными значениями (например, фиксированные значения текучести и найма/увольнения по отделам).
  - По умолчанию установлено: `DATA_MODE = "real"`.

- **Целевой период отчёта**:
  - В коде зафиксирована дата отчёта:
    - `now = datetime(2025, 12, 31)` — конец декабря 2025 года.
  - Год отчёта: `TARGET_YEAR = now.year`.
  - Месяц для отображения на титульных страницах определяется через русские названия месяцев `MONTH_NAMES_RU`.

## Структура данных и предобработка

### Основные датафреймы

- **`df_main_raw`** — исходные данные с листа `Список сотрудников`.
- **`df_term_raw`** — исходные данные с листа `Увольнение`.
- **`df_main`** — нормализованная версия `df_main_raw`:
  - `hire_date` — дата трудоустройства:
    - берётся из столбца `Дата трудоустройства` (по имени) **либо**
    - по индексу столбца (U, индекс 20), если имя не найдено.
  - `termination_date_hr` — `NaT`, так как даты увольнения для действующих сотрудников отсутствуют.
  - `birth_date` — дата рождения из `Дата рождения`.
  - `department` — фактический отдел из `ОтделФакт`.
  - `gender_raw` — нормализованный пол на основе столбца `Пол`.
- **`df_term`** — нормализованная версия `df_term_raw`:
  - `hire_date` — аналогично, дата приёма.
  - `termination_date` — дата увольнения:
    - из столбца `Дата увольнения` или по индексу столбца (V, индекс 21).
  - `birth_date`, `department`, `gender_raw` — по тем же принципам.

- **`df_all`** — объединённый датафрейм для помесячного анализа:
  - Объединение (`concat`) записей из `df_main` и `df_term`.
  - Поля: `ФИО`, `hire_date`, `termination_date`, `birth_date`, `department`, `gender_raw`.
  - Удаление дубликатов по комбинации `["ФИО", "hire_date"]`.

### Нормализация пола

- Функция `normalize_gender` приводит значение пола к:
  - `'м'` — если первая буква строки после приведения к нижнему регистру — `м`.
  - `'ж'` — если первая буква — `ж`.
  - `None` — во всех остальных случаях (пусто, другие символы).

### Базовые диагностические проверки

Скрипт выводит в консоль диагностическую информацию:

- Список столбцов и их наличие:
  - Проверка наличия `Пол`, `Дата рождения`, `ФИО`, `Дата увольнения`.
- Количество записей по листам и базовую статистику:
  - Сколько записей с ФИО.
  - Сколько записей с датой увольнения.
  - Сколько записей с заполненным полом.
- Диагностика после нормализации пола:
  - Уникальные значения пола после нормализации.
  - Количество мужчин и женщин по `df_main`.

## Рассчитываемые метрики

### Индивидуальные показатели по сотрудникам

- **Возраст (`age`)**:
  - Рассчитывается как \((now - birth_date) / 365.25\).
  - Вычисляется для всех записей с ненулевой датой рождения.

- **Стаж (`tenure`)**:
  - Рассчитывается как \((now - hire_date) / 365.25\).
  - Вычисляется для всех записей с ненулевой датой приёма.

### Сводные показатели (верхние метрики)

Из исходных таблиц и помесячных рядов вычисляются:

- **Общая численность персонала**:
  - Изначально — количество записей с заполненным `ФИО` в `df_main`.
  - Затем синхронизируется с помесячным рядом `headcount_7` (берётся значение за последний месяц).

- **Средний стаж**:
  - Изначально — среднее значение `tenure` по `df_main_with_data` (записи с ФИО).
  - Затем синхронизируется с последним значением ряда `avg_tenure_7`.

- **Средний возраст**:
  - Аналогично, сначала по всем записям `df_main`, затем из `avg_age_7` (последний месяц).

- **Распределение по полу**:
  - Счётчики мужчин и женщин по `gender_raw`:
    - `male_count`, `female_count`.
  - В дальнейшем синхронизируются с последним месяцем рядов `male_count_7` и `female_count_7`.

### Найм и увольнения

- **Период: с начала года (YTD)**:
  - Граница:
    - `year_start = datetime(TARGET_YEAR, 1, 1)`.
  - **Принято с начала года (`hired_ytd`)**:
    - Количество записей в `df_main`, у которых `hire_date` находится в интервале `[year_start; current_month_end]`.
  - **Уволено с начала года (`terminated_ytd`)**:
    - Количество записей в `df_term` с `termination_date` в этом же интервале.

- **Текущий месяц**:
  - Границы:
    - `month_start` — первый день целевого месяца.
    - `month_end` — последний день целевого месяца.
  - **Принято за месяц (`hires_month`)**:
    - Число сотрудников в `df_main` с `hire_date` в пределах текущего месяца.
  - **Уволено за месяц (`terms_month`)**:
    - Число записей в `df_term` с `termination_date` в пределах текущего месяца.

### Текучесть персонала

- **Текучесть за год (`turnover_ytd`)**:
  - Для `DATA_MODE = "demo"`:
    - Используются фиксированные значения (например, `17.3%`).
  - Для `DATA_MODE = "real"`:
    - Оценка численности на начало года:
      - `headcount_year_end` — текущая численность (по `df_main`).
      - `headcount_year_start = headcount_year_end - hired_ytd + terminated_ytd`.
      - Отрицательные значения обрезаются до 0.
    - Средняя численность:
      - `avg_headcount_ytd = (headcount_year_start + headcount_year_end) / 2`.
    - Текучесть:
      - \(\text{turnover\_ytd} = \dfrac{\text{terminated\_ytd}}{\text{avg\_headcount\_ytd}} \times 100\%\).

- **Текучесть за период (`turnover_period`)**:
  - Период: последние 30 дней относительно `now`.
  - Активные на начало периода:
    - Сотрудники из `df_main` с `hire_date` ≤ `period_start` и с заполненным `ФИО`.
  - Уволенные за период:
    - Записи в `df_term` с `termination_date` внутри периода.
  - Формула:
    - \(\text{turnover\_period} = \dfrac{\text{terminated\_period}}{\text{active\_period}} \times 100\%\).

## Помесячные ряды (последние 7 месяцев)

Для последних 7 месяцев рассчитываются следующие ряды:

- **Временные метки**:
  - `month_labels_7` — полные русские названия месяцев.
  - `month_labels_7_short` — сокращённые подписи (первые 3 буквы).

- **Численность и демография**:
  - `headcount_7` — численность на конец каждого месяца.
  - `avg_tenure_7` — средний стаж на конец каждого месяца.
  - `avg_age_7` — средний возраст на конец каждого месяца.
  - `male_count_7`, `female_count_7` — количество мужчин и женщин.
  - `male_pct_7`, `female_pct_7` — доля мужчин и женщин в процентах.

- **Текучесть**:
  - `turnover_series_7` — помесячный коэффициент текучести (%).
  - `terminations_7` — количество увольнений за месяц.
  - `male_turnover_7`, `female_turnover_7` — текучесть по полу (%) за месяц.
  - `male_termed_7`, `female_termed_7` — число уволенных мужчин и женщин.

Методика:

- Для каждого месяца:
  - Определяются `m_start` и `m_end` (начало и конец месяца).
  - Активные на конец месяца (`active_end_m`) считаются по `df_all` с учётом дат приёма и увольнения.
  - Активные на начало месяца (`active_start_m`) аналогично.
  - Среднесписочная численность за месяц:
    - среднее между активными на начало и конец месяца (общая и по полу).
  - Текучесть за месяц:
    - \(\dfrac{\text{количество увольнений за месяц}}{\text{среднесписочную численность}} \times 100\%\).

В режиме `demo` помесячный ряд текучести (`turnover_series_7`) заменяется фиксированными значениями для заданных месяцев.

## Аналитика по отделам

Для текущего месяца формируются показатели по отделам:

- **Режим `demo`**:
  - Используется заранее заданный список отделов с фиксированными значениями:
    - Название отдела (`name`).
    - Принято (`hired`).
    - Уволено (`terminated`).
  - Данные сортируются по общему числу движений и используются для торнадо‑диаграммы.

- **Режим `real`**:
  - Перебираются уникальные значения `department` в `df_main`.
  - Для каждого отдела считаются:
    - `hired_dept` — количество приёмов за текущий месяц.
    - `term_dept` — количество увольнений за текущий месяц (по `df_term`).
  - Фильтруются отделы, по которым есть хотя бы одно событие.
  - Данные сортируются по сумме `hired + terminated` и берутся топ‑10.

Полученные списки:

- `dept_names` — названия отделов.
- `dept_hired_list` — принятые по отделам.
- `dept_term_list` — уволенные по отделам (значения берутся со знаком минус для построения торнадо‑диаграммы).

## Генерация PDF‑отчёта

Выходной файл: **`HR-отчет.pdf`** (сохраняется в корень проекта).

Используется `matplotlib.backends.backend_pdf.PdfPages`, создаются две страницы:

### Лист 1: Общие HR‑показатели

- **Заголовок**:
  - Текст `HR-аналитика` + месяц и логотип `SDS`.

- **KPI‑карточки (ряд 2)**:
  1. **Количество сотрудников**:
     - Текущее значение численности.
     - Линейный график численности за последние 7 месяцев с подписями.
  2. **Средний стаж**:
     - Текущее среднее значение стажа (лет).
     - Линейный график средней длины стажа по месяцам.
  3. **Средний возраст**:
     - Текущее среднее значение возраста (лет).
     - Линейный график среднего возраста по месяцам.

- **Блок гендерной структуры (ряд 3)**:
  - **Слева** — круговая диаграмма:
    - Распределение сотрудников по полу (мужчины / женщины).
    - Подписи: количество и доля в процентах.
    - Легенда с обозначением полов.
  - **Справа** — сгруппированная столбчатая диаграмма:
    - Доля мужчин и женщин (%) по месяцам за последние 7 месяцев.
    - Подписи процентов над столбцами.

### Лист 2: Найм / Увольнения

- **Верхний блок**:
  - Логотип и заголовок `HR-аналитика` + месяц.
  - Карточки:
    - Принято сотрудников с начала года (`hired_ytd`) — с зелёным индикатором.
    - Уволено сотрудников с начала года (`terminated_ytd`) — с красным индикатором.

- **Средний блок KPI (2 колонки)**:
  - **Левая колонка**:
    - Принято сотрудников за текущий месяц (`hires_month`).
    - Уволено сотрудников за текущий месяц (`terms_month`).
  - **Правая колонка**:
    - Текучесть за год (`turnover_ytd`).
    - Текучесть за период (`turnover_period`).

- **Нижние графики**:
  - **Слева** — торнадо‑диаграмма:
    - Принятые и уволенные по отделам за текущий месяц.
    - Столбцы:
      - Приём — зелёный (вправо).
      - Увольнение — красный (влево, отрицательные значения).
    - Подписи значений внутри столбцов.
  - **Справа** — динамика коэффициента текучести:
    - Линейный график помесячных значений `turnover_series_7`.
    - Подписи значений (%) над точками.

- **Футер**:
  - Логотип `SDS` в нижней части страницы.

## Запуск проекта

### Локальный запуск (без Docker)

1. Установите Python 3.11 (или совместимую версию).
2. Установите зависимости:

```bash
pip install -r requirements.txt
```

3. **Запуск с данными из URL (по умолчанию)**:

```bash
python main.py
```

Данные будут автоматически загружены с сервера.

4. **Запуск с локальным файлом** (опционально):

Установите переменную окружения:

```bash
# Windows PowerShell
$env:DATA_FILE_PATH="C:\path\to\your\Data.xlsx"
python main.py

# Linux/Mac
export DATA_FILE_PATH="/path/to/your/Data.xlsx"
python main.py
```

5. По завершении работы будет создан файл `HR-отчет.pdf` в корне проекта.

### API сервер

Проект также включает FastAPI сервер для генерации отчетов через HTTP API.

1. Запустите сервер:

```bash
uvicorn api:app --reload
```

2. **Генерация отчета из данных на сервере**:

```bash
# GET запрос - данные загружаются автоматически с сервера
curl -X GET http://localhost:8000/generate-report-from-server --output HR-отчет.pdf
```

Или откройте в браузере: `http://localhost:8000/generate-report-from-server`

3. **Генерация отчета из загруженного файла**:

```bash
# POST запрос с файлом
curl -X POST http://localhost:8000/generate-report \
  -F "file=@/path/to/your/Data.xlsx" \
  --output HR-отчет.pdf
```

Документация API доступна по адресу: `http://localhost:8000/docs`

При этом:

- Рабочая директория внутри контейнера — `/app`.
- По умолчанию `Data.xlsx` ожидается по пути, зашитом в `main.py`.  
  При необходимости можно:
  - Изменить `DATA_FILE_PATH` в `main.py` и пересобрать образ.
  - Либо смонтировать файл в контейнер по нужному пути.

Результирующий `HR-отчет.pdf` будет создан в директории `/app` внутри контейнера.  
Чтобы получить его на хост‑машине, смонтируйте том или директорию:

```bash
docker run --rm -v %cd%:/app hr-report
```

(для Windows PowerShell; текущая папка будет использована как рабочая и для входных данных, и для выходного PDF).

## Как адаптировать проект под свои данные

- **URL файла на сервере**:
  - Измените значение `DATA_FILE_URL` в начале `main.py` или установите переменную окружения `DATA_FILE_URL`.

- **Локальный Excel‑файл**:
  - Установите переменную окружения `DATA_FILE_PATH` или передайте путь в параметре функции `generate_report(data_file_path="путь/к/файлу")`.

- **Структура столбцов**:
  - Важно, чтобы следующие столбцы присутствовали (по названиям или индексам столбцов, как в коде):
    - `ФИО`
    - `Пол`
    - `Дата рождения`
    - `Дата трудоустройства`
    - `Дата увольнения` (для листа с увольнениями)
    - `ОтделФакт`

- **Режим `demo`**:
  - Если хотите протестировать внешний вид отчёта без реальных данных, установите:

```python
DATA_MODE = "demo"
```

  - В этом режиме используются фиксированные значения для части метрик и аналитики по отделам.

## Итог

Данный проект — это полностью автономный генератор HR‑отчёта в формате PDF, рассчитанный на работу с реальными данными Excel.  
Он автоматизирует расчёт ключевых HR‑метрик (численность, стаж, возраст, текучесть, найм/увольнения, гендерная структура) и оформляет результаты в наглядном двухстраничном отчёте, готовом к использованию в презентациях и управленческой отчётности.
